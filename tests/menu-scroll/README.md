# Windowless menu regression tests

Run `bash tests/menu-scroll/run.sh` in the maintainer Linux/WSL environment with GCC and SDL2 development headers installed. No window or global input is used. All configuration reads/writes are redirected to `.build/menu-tests`.

The harness compiles the production DJUI tree/layout, text wrapping, widgets, cursor, input handling, panel transitions, bindings, rule setters, SDL controller reader, and config serializer/parser. OS/GPU/audio and unrelated gameplay services are inert adapters. Font measurements use the source's actual normal-font width table. A process-local SDL virtual controller exercises the entire input-to-preset path; no physical controller or global input is used. Any attempted network send fails the test. Online rule/network authority is separately tested by `codex/rocketleague/tests/test_boost_mode.sh`, and gameplay bindings by `test_bindings.sh`.

Difficulty regression coverage starts at Medium, presses/releases PlayStation X/Cross through the actual saved south-button mapping, and verifies repeated Hard -> Easy -> Medium cycles. It checks holding without repeats, release rearming, an Xbox X/west remap, keyboard Enter, mouse arrows in both directions, leaving derived Custom through either arrow, keeping custom values across rendering/reload, and restoring the selection after a failed atomic save followed by a successful retry. The test failed on the prior UI at the second Cross press: SDL delivered `8000` again, but Hard remained selected because Custom was rejected as a preset. The fix skips only that derived display slot.

The matrix covers 320×240, 640×360, 640×480, 1280×720, 1920×1080, 2560×1080 and 800×1280, side and centered layouts, and all four fixed UI-scale choices. It checks every interactive control in Settings, Controls, Car Controller, Driving, Air/Slide and native binding menus; sequential traversal of offscreen rows; first/last wrapping through keyboard and controller direction paths; wheel offset clamping; nested binding geometry; submenu return focus; capture isolation on the first frame; Escape cancel without changing a binding; successful rebinding/save/reload; surface changes/save/reload; live resizing while retaining focus; and long labels/values. A separate executable compiles the real UI scaling function and checks 35 resolution/scale combinations including Auto.

The UI harness runs under AddressSanitizer and UndefinedBehaviorSanitizer. Outputs are logs and SVG layout renders under `.build/menu-tests`. These are source-test renders with representative glyph drawing and inert arrow textures, **not screenshots of a running game**. They demonstrate computed layout/clipping using the actual rule descriptions. A headless browser can render them to PNG for inspection without using the user's desktop.

Physical controller use and visual acceptance in the full game remain a coordinated manual check. The tests do not claim a full game session or reproduce the unavailable original screenshot.
